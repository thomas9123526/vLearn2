# vLearn2 — Flutter app source description (part 1)

This document walks through the Flutter application source tree
under `flutter_app/`, file by file at the *what does it own* level,
and explains how they connect. The second half covers
Android-vs-Windows splits — what's shared, where the codebase branches,
and how to add new platform-specific logic (with the
`getMachineID()` license example).

---

## 1. Top-level layout

```
flutter_app/
  pubspec.yaml                 // dependencies
  android/                     // Android-only native shell
  windows/                     // Windows-only native shell
  lib/                         // all Dart code
  assets/                      // animations, fonts, icons
  build/                       // generated; ignored by git
```

`lib/` is the only place we write Dart. Everything outside is
generated by Flutter (`android/`, `windows/`) or static assets.

## 2. `lib/main.dart`

Entry point. Three things happen in `main()` before `runApp`:

1. `WidgetsFlutterBinding.ensureInitialized()` — required for any
   `await` before `runApp`.
2. `sherpa_onnx.initBindings()` — wires up the speech FFI bindings.
   Without it, the first `OfflineTts` constructor throws.
3. `await rive.RiveNative.init()` — loads the rive 0.14 native
   renderer + font subsystem.
4. On Android, `_requestAndroidStorage()` requests
   `MANAGE_EXTERNAL_STORAGE` / `READ_EXTERNAL_STORAGE` /
   `WRITE_EXTERNAL_STORAGE` so the app can read the public
   `룡마/가상외국어회화/app_config.json` location.
5. `appConfigProvider.future` is awaited so Dio gets the real
   `baseurl` before any provider that depends on it builds.

`runApp` mounts `VLearn2App` inside an `UncontrolledProviderScope`
that holds the pre-warmed `ProviderContainer`.

## 3. `lib/core/`

Cross-cutting concerns. Subfolders:

### 3.1 `core/api/`

Dio HTTP layer. Files:

| File | Owns |
| --- | --- |
| `api_client.dart` | `apiClientProvider`, the singleton Dio. Composes `BaseOptions`, attaches interceptors. Also owns `TokenStore` (secure storage with an in-memory race-safe mirror). |
| `auth_api.dart` | `/auth/*` requests — signUp, signIn, lookupUsernameByCid, me, signOut. |
| `app_apis.dart` | Aggregates feature APIs (users, scenarios, personas, conversations, news, progress) into a single re-export. |
| `interceptors/auth_interceptor.dart` | Attaches `Authorization: Bearer …`. Handles 401 → refresh → retry. Single mutex so concurrent 401s share one refresh call. |
| `interceptors/error_interceptor.dart` | Normalises Dio errors into `ApiException { statusCode, i18nKey?, message }`. |
| `interceptors/compression_interceptor.dart` | gzips request bodies > 1 KB. |
| `interceptors/request_log_interceptor.dart` | Debug-only `[→ POST …]` / `[← 200 …]` console traces. |
| `interceptors/network_interceptor.dart` | Short-circuits requests when `NetworkStatusService` is offline. |

### 3.2 `core/auth/`

`remembered_credentials.dart` — secure store for the "Save my
account" toggle on the sign-in screen.

### 3.3 `core/config/`

`app_config.dart` — the on-disk JSON config. Owns:

* `AppConfig` immutable value object (`baseurl`, `reqTout`, `tSync`,
  `dev`, `modelPath`).
* `ConfigFileService` — resolves the path per-platform (Android:
  `/storage/emulated/0/룡마/가상외국어회화/app_config.json`; Windows:
  alongside the .exe; others: `applicationSupport`), reads, writes,
  and creates the default on first launch.
* `appConfigProvider` — `FutureProvider<AppConfig>`.
* `AppConfig.logx(tag, msg)` — `debugPrint` wrapper used across the
  app for tagged logging.

`layout_config_provider.dart` — fetches `/app-config/layout` and
exposes flag visibility for tabs (`tabs.home`, `tabs.scenarios`, …).

### 3.4 `core/network/`

Task 18 additions:

* `network_status.dart` — `NetworkStatusService` wrapping
  `connectivity_plus`, three-state status, `networkStatusProvider`
  stream.
* `offline_banner.dart` — `OfflineBanner` widget mounted once in
  `AppShell` above the active route.

### 3.5 `core/speech/`

Push-to-talk capture + sherpa-onnx STT/TTS. Files:

| File | Owns |
| --- | --- |
| `audio_recorder.dart` | `AudioRecorderService` wraps `record` plugin. PCM16, mono, 16 kHz. Lifecycle: `requestPermission → start → stop → AudioCapture`. |
| `speech_service.dart` | Abstract `SpeechToTextService` / `TextToSpeechService` + a stub no-op implementation for tests. `sttServiceProvider`, `ttsServiceProvider`, `speechReadyProvider`. |
| `sherpa_onnx_stt.dart` | Real STT. Picks online-transducer vs whisper based on manifest contents. |
| `sherpa_onnx_tts.dart` | Real TTS. Synthesises Float32 PCM, wraps in WAV, plays via `audioplayers`. Caches WAVs by `sha256(text|voiceId|rate)`. |

### 3.6 `core/storage/`

| File | Owns |
| --- | --- |
| `model_registry.dart` | `ModelRegistry` resolves the on-disk model root (override > `.dat` unpacked > placeholder), verifies SHA-256 of every listed file (skipped for admin-placed overrides where the manifest is synthesized). |
| `auth_history.dart` | Marks whether the user has ever signed in (drives splash CTA: "Sign in" vs "Sign up"). |

### 3.7 `core/datapack/`

`datapack_paths.dart` + `datapack_installer.dart` — the `.ddp`
unpacker that materialises the on-device speech models. Pure Dart
crypto (pointycastle): SHA-256, HKDF, AES-GCM, ECDH, ECDSA. Driven
by the speech-setup screen on first launch when no model override
is configured.

### 3.8 `core/errors/`

`polite_error.dart` — `politeMessageFor(error, context, i18nKey)`
maps every error class into a single short user-facing sentence.
Also exports `PoliteBanner`, `PoliteErrorCenter`,
`showPoliteErrorSnack`, and `logRawError` for the debug console.

### 3.9 `core/models/`

`models.dart` — barrel export of every domain class (`UserProfile`,
`Persona`, `Scenario`, `ConversationMessage`, `NewsPost`, etc.) with
`fromJson` / `toJson` constructors. Tied to the backend DTO shapes.

### 3.10 `core/providers/`

Riverpod glue. The big two are:

* `auth_provider.dart` — `AuthNotifier` (StateNotifier),
  `authProvider`, sign-in / sign-up / sign-out, profile refresh.
* `settings_provider.dart` — theme key, font group, locale,
  language settings backed by `shared_preferences`.

### 3.11 `core/router/`

`app_router.dart` — single `routerProvider<GoRouter>`. Owns:

* Top-level redirect that gates routes by auth state.
* Splash route resolution (splash → sign-in / sign-up depending on
  history).
* Speech-models gate (sends users to `/speech-models` if the model
  bundle is missing).
* Shell route mounting the four-tab `AppShell`.

### 3.12 `core/services/`

`cid_fetch_service.dart` — stub network probe that returns the
device's CID (today returns a placeholder string for dev). Will
become a real network call when the org-wide CID lookup endpoint
ships.

### 3.13 `core/theme/`

`app_theme.dart` — `AppTheme.build(themeKey, fontGroup)` produces a
`ThemeData` per palette × font pair. Four palettes (apricot, sage,
iris, obsidian) × three font groups (editorial, modern, classic).

## 4. `lib/features/`

One folder per top-level feature, each owning its screens, widgets,
and providers.

| Folder | Owns |
| --- | --- |
| `auth/` | `SignInScreen`, `SignUpScreen`, `SplashScreen`. |
| `home/` | `HomeScreen` — top-of-app dashboard, daily streak, recent activity, bell icon. |
| `news/` | `NewsListScreen`, `NewsDialog` (the modal launched from the bell), `news_providers.dart`. |
| `conversation/` | The big one. `ConversationScreen` orchestrates session lifecycle. `TutorModeView` is the voice-only fullscreen view; `ChatModeView` is the typing variant. `widgets/tutor_avatar.dart` renders the Rive avatar; `widgets/cartoon_face.dart` is the fallback painter. |
| `scenarios/` | List + detail (description) screens. |
| `progress/` | XP / level / streak chart. |
| `settings/` | `SettingsScreen` + edit-profile dialog. |
| `history/` | Conversation history list and per-session detail. |
| `speech_models/` | Speech setup screen (datapack unpack progress + manifest verification). |
| `model_diagnostics/` | Hidden screen reachable from settings — surfaces which model files exist on disk and their hash status. |

## 5. `lib/shared/`

Cross-feature widgets. `widgets/app_shell.dart` is the four-tab
chrome (sidebar on desktop, bottom nav on mobile). Wrapped with the
`OfflineBanner` from task 18.

## 6. How it all connects

A typical user turn ("user taps mic in TutorMode, says a sentence,
hears a reply") traverses:

```
TutorModeView (features/conversation/widgets/tutor_mode_view.dart)
   │ recorder.start()  ── ref.read(audioRecorderProvider)
   ▼
AudioRecorderService (core/speech/audio_recorder.dart)
   │ record plugin → PCM16 mono 16k bytes
   ▼
recorder.stop() returns AudioCapture
   │
   ▼
SherpaOnnxSttService.transcribe()  (core/speech/sherpa_onnx_stt.dart)
   │ float32 conversion → online transducer / whisper
   ▼
SttResult { text, audioDuration, … }
   │ widget.onSendText(text)
   ▼
ConversationScreen state notifier (features/conversation/...)
   │ ConversationsApi.sendMessage() ── core/api/app_apis.dart
   ▼
Dio (core/api/api_client.dart)
   │ NetworkInterceptor → AuthInterceptor → request → backend
   ▼
Response: { assistantMessage, grammarScore, scenarioState, … }
   │
   ▼
state.messages updated → didUpdateWidget on TutorModeView
   │
   ▼
_maybeSpeakLatestAssistantReply()
   │ tts.speak(text, voiceId)
   ▼
SherpaOnnxTtsService (core/speech/sherpa_onnx_tts.dart)
   │ generate → wav → audioplayers.play
   ▼
isSpeakingStream → _mood = TutorMood.speaking → avatar mouth cycle
```

# Part 2 — Android vs Windows: where the code branches

Most of `lib/` is platform-agnostic. The split happens in three
places:

## A. Native plugin layer

Plugins like `flutter_secure_storage`, `record`, `path_provider`,
`audioplayers`, `permission_handler`, `connectivity_plus`,
`sherpa_onnx`, `rive_native` provide their own per-platform
implementations. We don't write any of those — we just opt in via
`pubspec.yaml`. Each plugin's `android/` and `windows/` folders
inside the package handle the platform-specific bits.

## B. Dart-side `Platform.is*` branches

`dart:io`'s `Platform.isAndroid` / `Platform.isWindows` /
`Platform.isLinux` is the standard way to fork behaviour. Existing
uses:

| Path | What forks |
| --- | --- |
| `core/config/app_config.dart` (`ConfigFileService.resolveConfigFile`) | Android: public `/storage/emulated/0/룡마/가상외국어회화/`; Windows: same folder as `.exe`; other: `applicationSupport`. |
| `lib/main.dart` (`_requestAndroidStorage`) | Only runs the storage-permission requests on Android. |
| `flutter_app/android/app/src/main/AndroidManifest.xml` | Android-only `MANAGE_EXTERNAL_STORAGE` + cleartext network policy. |
| `flutter_app/android/app/src/main/res/xml/network_security_config.xml` | Android-only cleartext allowlist (localhost, 10.0.2.2). |
| `flutter_app/windows/runner/` | Windows-only `main.cpp` (auto-generated by Flutter; we don't edit). |

## C. Method channels (when no plugin exists)

The pattern for "I need a value the OS gives me but no plugin
covers it" is:

1. Create a `MethodChannel('com.vlearn2/<name>')` in Dart.
2. Implement the handler in `android/app/src/main/kotlin/...` for
   Android and `windows/runner/...` for Windows.
3. Each native handler returns the platform-specific value.
4. The Dart side branches on `Platform.isAndroid` only to *select*
   the channel; the call itself is identical.

This is exactly the pattern needed for the upcoming `getMachineID()`.
See section D.

## D. Worked example — `getMachineID()`

The license feature (todo 17) needs a per-device machine ID:

* Android: a stable hash of `Settings.Secure.ANDROID_ID` (or a
  combination including `Build.SERIAL` via JNI in
  `AndroidDevIDLib.aar`).
* Windows: WMI `Win32_BIOS.SerialNumber` or
  `MachineGuid` from the registry, exported by a VS2022 DLL
  (`WindowsDevIDLib.dll`).

The Flutter side stays one file:

```dart
// lib/core/license/machine_id_service.dart
class MachineIdService {
  static const _channel = MethodChannel('com.vlearn2/machine_id');

  Future<String> get() async {
    final id = await _channel.invokeMethod<String>('get');
    if (id == null || id.isEmpty) {
      throw StateError('Native getMachineID() returned empty');
    }
    return id;
  }
}
```

On the Android side (Kotlin):

```kotlin
// android/app/src/main/kotlin/.../MainActivity.kt
class MainActivity : FlutterActivity() {
  override fun configureFlutterEngine(flutterEngine: FlutterEngine) {
    super.configureFlutterEngine(flutterEngine)
    MethodChannel(
      flutterEngine.dartExecutor.binaryMessenger,
      "com.vlearn2/machine_id",
    ).setMethodCallHandler { call, result ->
      if (call.method == "get") {
        try {
          // Delegate to AndroidDevIDLib.aar — calls into JNI.
          result.success(AndroidDevID.getDeviceId(applicationContext))
        } catch (e: Throwable) {
          result.error("MACHINE_ID", e.message, null)
        }
      } else {
        result.notImplemented()
      }
    }
  }
}
```

On the Windows side (C++):

```cpp
// windows/runner/flutter_window.cpp
void RegisterMachineIdChannel(flutter::FlutterEngine* engine) {
  auto channel = std::make_unique<flutter::MethodChannel<>>(
      engine->messenger(), "com.vlearn2/machine_id",
      &flutter::StandardMethodCodec::GetInstance());
  channel->SetMethodCallHandler([](const auto& call, auto result) {
    if (call.method_name() == "get") {
      // Calls into WindowsDevIDLib.dll
      auto id = WindowsDevID_Get();
      if (id) {
        result->Success(flutter::EncodableValue(std::string(id)));
      } else {
        result->Error("MACHINE_ID", "failed");
      }
    } else {
      result->NotImplemented();
    }
  });
  // store channel handle somewhere persistent — engine owns lifetime
}
```

This pattern is repeatable for every "I need OS X to tell me Y"
moment: license checks, hardware capabilities, sensor data,
clipboard variants, anything not already covered by a pubspec
plugin.

## E. Recap — what the codebase splits on, and where

| Concern | How it splits |
| --- | --- |
| Storage paths | `Platform.is*` in `ConfigFileService` |
| Permissions | `Platform.isAndroid` gate around `permission_handler` calls |
| Network reachability | `connectivity_plus` plugin (no Dart fork) |
| Mic capture | `record` plugin (no Dart fork) |
| TTS/STT | `sherpa_onnx` FFI (no Dart fork) |
| Animation | `rive_native` (no Dart fork) |
| Machine ID (upcoming) | Method channel with native AAR / DLL backend |
| Network security (cleartext) | Android-only `network_security_config.xml` |

When the codebase needs a new platform-specific value, the pattern
is: try a plugin first, drop to a method channel + native bridge
only when no plugin fits. The Dart side stays one file; the per-
platform native bits live in `android/app/src/main/kotlin/` and
`windows/runner/`.
