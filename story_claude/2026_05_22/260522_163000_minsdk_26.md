# Android minSdk raised 24 → 26

## What changed

`flutter_app/android/app/build.gradle.kts` — `defaultConfig.minSdk`
raised from `24` to `26`. The app's minimum supported platform is now
**API 26 (Android 8.0)**.

## Why it's safe

- The build already worked at `minSdk = 24`, so every plugin's own
  minimum is ≤ 24 — raising the floor to 26 can't introduce a
  manifest-merger conflict (you only ever get those raising *into* a
  plugin's higher requirement, never away from it).
- Flutter's own minimum is well below 26.
- The storage model is unaffected: the manifest's legacy
  `READ/WRITE_EXTERNAL_STORAGE` (with `maxSdkVersion` caps) and
  `MANAGE_EXTERNAL_STORAGE` already span API 26 correctly — API 26 =
  Android 8.0 uses the legacy runtime storage permission.
- `abiFilters` (arm64-v8a + x86_64), `targetSdk = 35`, `compileSdk`,
  and the native-splash config are all independent of `minSdk` and
  need no change.

## Implication

The app is **no longer installable on API 24/25** (Android 7.0 /
7.1). Those are a small, shrinking user base; API 26 (2017) is a
reasonable floor.

## Not done

No build run here — `minSdk` is a manifest `uses-sdk` value, it
doesn't affect Dart or Kotlin compilation, and a raise from a
known-good 24 to 26 can't fail the manifest merge. `flutter build
apk` on the next real build will carry it through.
