tasks needed code changes; four were investigative.

| # | Task | Type | Outcome |
|---|---|---|---|
| 05 | Android post-build gradle script | implementation | Added `postBuildResguard` `Exec` task finalized onto `assembleRelease`, runs the user's external `build_apk.bat`. Trimmed `abiFilters` to `arm64-v8a` + `x86_64` so the legacy `armeabi-v7a` `.so` files never make it into the APK. |
| 06 | Scenario images on app | audit | The Flutter app does NOT render scenario images today. Schema + model + API all carry `image_url`; only the view layer is missing. Same applies to personas. Report flags the 4 surfaces that would consume it. |
| 07 | App ↔ backend DB sync | audit | The Drift schema in `lib/core/db/` is complete (read-through cache for users / scenarios / sessions / progress / settings / layout) but is **never wired** — no provider, no repository, no call site. All data flow is online-only via Dio + Riverpod's in-memory FutureProviders. |
| 08 | Illegal-word guard during AI chat | audit | Both Flutter `ContentGuard` and backend `ContentGuardService` are defined, tested, registered, and ship wordlists — but **neither is invoked** from the chat send path. Partial implementation, ~10 lines each side to wire. |
| 09 | News via dialog on home | implementation | Created `widgets/news_dialog.dart` (`showNewsDialog`) that mirrors `NotifModal` from `screens.jsx`: dialog hosts a list view that swaps to in-place detail on tap. Bell icon and news-strip cards both now open the dialog (with optional `initialSlug`) instead of pushing fullscreen `/news` routes. |
| 10 | Downgrade backend to Node 12 | audit + decision | Not feasible without rewriting NestJS / TypeORM / OpenAI / Anthropic / Sharp / bcrypt against ancient API surfaces, and Node 12 has been EOL since 2022-04-30. Recommended staying on Node 20 LTS and containerizing if the host is constrained. |
| 11 | Relax password rule to length-only | implementation | Replaced `MinLength(8)` + three `Matches(/[a-z]/,/[A-Z]/,/[0-9]/)` chains with `MinLength(6)` everywhere — `auth.dto`, `user.dto`, the Flutter sign-up validator, the change-password dialog's inline check, and the form helper copy. |
| 12 | Admin-driven password reset | implementation | New permission `users.reset_password` (grantable to sub-admins). New endpoint `POST /admin/users/:id/reset-password` that bcrypt-hashes the new password, overwrites `password_hash`, and **deletes every active refresh token** for that user. Admin panel got a "Reset Password" button + modal on the Users tab. Audit log entry records the action and the count of revoked sessions — never the password or hash. |
| 13 | Admin panel for Chrome ≥ 80 | implementation | Added explicit `.browserslistrc` floor (`Chrome >= 80, Edge >= 80, Firefox >= 78, Safari >= 14, not dead`), dropped `tsconfig.target` from `ES2022` → `ES2019`, and replaced the only Chrome-85+ runtime API in source (`.replaceAll(...)` in the dashboard layout breadcrumb) with `.split(...).join(...)`. |

## Decisions / call-outs

- **Audit-only tasks (06, 07, 08, 10) were left audit-only.** The
  prompts asked "is this implemented?" — answering with a report
  and not bolting on speculative implementation. Each report
  explicitly lays out what implementation would look like so the
  decision can be made later. Audit-only matches the task wording
  and avoids landing half-baked features (e.g., wiring the content
  guard would also need a violations-table insert path + admin
  review UI to actually be useful).
- **Tasks 05, 09, 11, 12, 13 needed code.** All landed minimal,
  contained changes verified clean by their respective type
  checkers and analyzers.
- **Auto-commit gathers all 9 into one commit.** They were
  produced in a single user-blessed batch ("read 05–13, do them
  all"), so a single commit keeps the report files and code
  changes coherent. Each task has its own md report; per-task
  history is preserved there.
- **The admin module gained one extra TypeORM entity registration**
  (`RefreshTokenEntity`). It's used by exactly one new endpoint;
  not pre-allocating for anything else.
- **Permission catalog ordering** keeps `users.reset_password`
  next to `users.suspend` (both day-to-day ops tasks), separate
  from the `users.edit_*` permissions which are more like
  "data-tweaking" actions.
