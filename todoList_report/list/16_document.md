# 16 — Full source description docs

Three "part 1" reference documents covering the Flutter app, the
NestJS backend, and the Next.js admin panel. Each is a per-file,
per-module tour with a worked end-to-end example at the bottom.

## Files produced

* `docs/0525/app_source_description_part1.md` + `.docx`
  Walks every `lib/` subfolder; names every important file with
  its role; traces a user turn from mic tap → STT → backend →
  TTS → mouth-sync. Bottom half covers Android-vs-Windows splits:
  three layers (native plugins, `Platform.is*` Dart branches,
  method channels) with a worked `getMachineID()` example
  (Kotlin + C++ + Dart side-by-side).
* `docs/0525/backend_api_part1.md` + `.docx`
  Module table for `backend/src/`, per-feature folder convention,
  worked sign-in request trace through `main.ts` → guards →
  `ValidationPipe` → `AuthService` → bcrypt → JWT issue.
* `docs/0525/admin_part1.md` + `.docx`
  Next.js App Router walkthrough — every route under
  `(dashboard)/`, components, hooks, lib utilities. Worked trace
  of an "edit scenario" flow through react-query +
  react-hook-form into the backend's transactional PATCH +
  audit log.

DOCX files were generated by pandoc from the matching MDs.

## Naming

The user asked for "part 1" semantics because the request says
"full document". Each surface really is multi-volume — part 2 of
each can come back later with deeper sections (per-route React
component breakdown, per-endpoint contract tables, etc.).
