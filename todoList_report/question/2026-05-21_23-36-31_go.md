## What you now have

Open the Run & Debug panel (Ctrl+Shift+D) and you'll see six configurations:

| Config | When to pick |
| --- | --- |
| **Flutter: debug (pick device)** | Use VS Code's device picker (bottom-right status bar) to choose between emulator / real device / Windows. Most common day-to-day. |
| **Flutter: debug — Android emulator (emulator-5554)** | Forces the running emulator. Doesn't need device selection. |
| **Flutter: debug — Windows desktop** | Native Windows build, fastest hot-reload cycle, no Android boot delay. |
| **Flutter: profile (perf testing)** | Profile build — release-ish optimisations + DevTools' performance tab works. Use this on a real device for splash/anim perf testing. |
| **Flutter: release** | Final shipping build. No debugger, no hot reload. Use to sanity-check a "what does the user see" scenario. |
| **Flutter: attach to running app** | If you launched via `flutter run` in a terminal and want VS Code's debugger to attach. |

## One requirement

VS Code needs the **Dart-Code.flutter** extension installed for the `"type": "dart"` entries to register. If it's missing:

```
View → Extensions → search "Flutter" → install the one by Dart Code
```

This also brings:
- Device picker in the status bar (bottom-right shows "Android Emulator" / "Windows" / etc.)
- "Dart: Open DevTools" command palette entry
- Squiggly underline + import quick-fix for Dart code

## Day-to-day flow

1. Make sure your Android emulator is running (it already is — `emulator-5554`).
2. F5 with **"Flutter: debug — Android emulator"** selected.
3. Set breakpoints in any `.dart` file by clicking the gutter.
4. Edit code → save → hit the **hot-reload** button in the debug toolbar (lightning bolt) — UI updates without losing state.
5. Open DevTools via Cmd Palette → "Dart: Open DevTools" → Inspector tab for widget tree, Network tab for HTTP, Performance tab for frame timing.

## For your `MANAGE_EXTERNAL_STORAGE`-dependent code

The `/sdcard/룡마/가상외국어회화/` paths only resolve correctly on a real Android device (the emulator may not properly model the permission flow). For datapack work specifically, plug in a real Android 11+ phone via USB:

```powershell
adb devices                                    # confirm it lists
flutter run -d <device-id>                     # or pick it from VS Code device picker
```

Then drop `.ddp` files into `/sdcard/룡마/가상외국어회화/datapacks/` via USB transfer and your installer code can find them.
