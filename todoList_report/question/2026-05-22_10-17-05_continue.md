## Direct answer to your question

**Yes** — unpacking *was* affecting the entire app, because it ran on the **main UI isolate**. Pure-Dart AES-GCM + zlib on tens-of-MB sherpa model files takes many seconds; the UI thread was blocked the whole time, so Android's watchdog popped the "isn't responding" dialog.

## What changed

The install now runs on a **background isolate** (`Isolate.run`). The split:

| Main isolate (fast, plugin-dependent) | Background isolate (slow, CPU-heavy) |
| --- | --- |
| Resolve sdcard paths (`path_provider`) | Parse PEM keys |
| Load admin key + root CA from assets | Scan + SHA-256 the `.ddp` files |
| | AES-GCM decrypt, zlib inflate |
| | SHA-256 verify, write files |

The UI thread is now free the whole time — the "Preparing your data…" spinner animates smoothly, and there's no ANR.

## What this fixes — and what it doesn't

- ✅ **Fixed:** the freeze and the ANR dialog. The app stays responsive.
- ❌ **Not changed:** total install *time*. Pure-Dart crypto is still slow — a big bundle still takes the same seconds to decrypt. But now you wait with a live spinner instead of a frozen app Android wants to kill.
