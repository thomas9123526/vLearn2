## Stage 9 next — app startup wiring

The unpacker is done. Stage 9 is pure plumbing on the Flutter side:

1. On app launch, scan a well-known external path (e.g. `/sdcard/DataManage/*.ddp`).
2. For each unfamiliar or updated `.ddp`, call `factory.unpack(packPath, outRoot)`.
3. Track previously-unpacked .ddp fingerprints in `getApplicationSupportDirectory()/datamanage_state.json` so we don't re-unpack on every launch.
4. If expected bundles aren't found, route to a friendly "please copy DataManage packs to /sdcard/DataManage/" screen (the existing `ModelsNotInstalledScreen` is a good landing pattern).

Question for you before Stage 9:

- **Where on the device should `.ddp` files live?** Two clean options:
  | Path | Pros | Cons |
  | --- | --- | --- |
  | `/sdcard/DataManage/*.ddp` (public external storage) | Admin can USB-transfer or use any file manager. Doesn't depend on app package name. | Needs `MANAGE_EXTERNAL_STORAGE` permission (you already have it). On Android 11+ the user has to approve the permission in a separate Settings screen. |
  | `/sdcard/Android/data/<package>/files/Packs/*.ddp` (app-specific external) | No extra permission needed. Admin sees it via USB too. | Path depends on package name (`com.example.flutter_app` or similar). |

I'd recommend **`/sdcard/DataManage/`** — simpler path for admins to remember, you already have `MANAGE_EXTERNAL_STORAGE` configured for the existing `룡마/가상외국어회화` folder, so the runtime-permission flow is the same. Tell me if you'd prefer the app-specific path.
