**How it works end-to-end**:

```
App launch
  │
  ├─ ProviderScope created
  ├─ VLearn2App.build → ref.watch(licenseStateProvider)
  │       ⇒ LicenseStateNotifier constructed
  │       ⇒ wires `ref.listen(authProvider, …)`
  │
  ├─ AuthNotifier._restore() restores session
  │       ⇒ AuthState.signedIn(user)
  │
  ├─ LicenseStateNotifier sees signedIn transition
  │       ⇒ reads SharedPreferences['license.cachedContent']
  │       ⇒ if present, POST /license/verify with cached content
  │       ⇒ updates LicenseStateSnapshot.result
  │
  └─ Admin Users page (admin browses it minutes/hours later)
          ⇒ sees fresh license_valid_until / license_platform
          ⇒ verify_log has a fresh entry per launch
```

**First-time activation still requires a manual scan/load** — the cache is empty until then. After the user activates once (QR scan on Android, `.lic` load on Windows), the base64 payload is persisted to `SharedPreferences`, and every subsequent app launch re-verifies automatically.

**Cache scope**: per-device, not per-user. The cert is bound to a `machineId`, so it's valid for whichever user signs in next on that device. Sign-out clears the in-memory snapshot but **leaves the cached payload on disk** so the next sign-in replays cleanly without re-scanning the QR.

**Failure modes** (all silent — verify is best-effort on launch):
- No cache → no-op, user must activate manually first.
- Network blip → previous in-memory state retained; can retry from the License screen.
- Cert revoked / expired → admin Users page reflects the new state on next refetch; user sees the updated card next time they open the License screen.
