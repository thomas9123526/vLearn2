Found it. There's a race condition involving `/app-config`:

1. User taps Sign In → `_submit` calls `authApi.signIn` (POST with `skipAuth: true`).
2. `CompressionInterceptor.onRequest` reads `backendGzipEnabledProvider`, which triggers `backendFlagsProvider` to build, which fires a Dio `GET /app-config` in the background.
3. At this moment there's no access token → the GET goes out **without** a Bearer header → backend returns **401**.
4. `AuthInterceptor.onError` sees 401, reads the refresh token (also missing — no session yet), and calls `onSessionInvalid()` → microtask → `forceSignOut()` → clears tokens, sets state to `signedOut`.
5. Meanwhile the sign-in POST returns, `_persistAndFetch` writes tokens, fetches profile, sets state to `signedIn` → router redirects to `/home` → home renders.
6. **Then** the `forceSignOut` microtask (or a second 401 it kicked off) clears the tokens that were just written and sets state to `signedOut` → router redirects `/home` → `/signin`.

The root cause is `AuthInterceptor.onError` invalidating the session on a request that **never carried a Bearer token in the first place**. A 401 to an anonymous request just means "no auth provided" — there's no session to tear down.

**The actual race** (not the credential-save path I patched in `556a1a0`):

1. User taps **Sign in** → `authApi.signIn` POSTs with `skipAuth: true`.
2. The first read of `CompressionInterceptor`'s `backendGzipEnabledProvider` transitively builds `backendFlagsProvider`, which fires a background `GET /app-config`.
3. No access token yet → that GET goes out **without** a `Bearer` header → backend (`@UseGuards(JwtAuthGuard)`) returns **401**.
4. Old `AuthInterceptor.onError`: 401 + no refresh token → `onSessionInvalid()` → microtask → `forceSignOut()` → clears tokens, state ⇒ `signedOut`.
5. Sign-in POST returns, `_persistAndFetch` writes tokens, fetches profile, sets state ⇒ `signedIn` → router redirects to `/home`, home renders.
6. The pending `forceSignOut` microtask wins the race **after** step 5 — wipes the just-issued tokens, state ⇒ `signedOut` → router redirects `/home` → `/signin`.
